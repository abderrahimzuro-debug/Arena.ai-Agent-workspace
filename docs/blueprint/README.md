## ملخص المنتج

Zuro Code بيئة تطوير بمساعدة الذكاء الاصطناعي تعمل كتطبيق Windows. يستخدم المستخدم مفاتيح API الخاصة به، ويستطيع ربط مزودين متعددين. يوزع النظام المهام على نماذج مختلفة وفق التخصص والتوافر والجودة والحصة، ويزودها بسياق محدود وأدوات ومهارات مناسبة.

## المبادئ الأساسية

1. **المستخدم يتحكم:** صلاحيات واضحة، وموافقة قابلة للضبط، وسجل قابل للمراجعة.
2. **المشروع محلي أولًا:** تعمل النماذج على نسخة محلية يحددها المستخدم، لا على حساب GitHub مباشرة.
3. **التنسيق مركزي:** المنسق يدير المهام والحالة المشتركة؛ لا تعدّل النماذج الملفات عشوائيًا.
4. **أقل سياق ممكن:** لا ترسل كامل المشروع أو المحادثة إلا عند الضرورة.
5. **قابلية الاستبدال:** واجهات موحدة للمزودين والأدوات والمهارات.
6. **لا وعود مجانية مضللة:** الخدمة المجانية مرتبطة بسياسات المزود المتغيرة.
7. **الأمان قبل الاستقلالية:** لا يملك النموذج وصولًا مباشرًا غير مقيد إلى نظام التشغيل.

## المصطلحات الأساسية

- **API:** واجهة تسمح للتطبيق بطلب خدمة من مزود خارجي.
- **Token:** وحدة نصية يعالجها النموذج؛ طريقة حسابها تختلف بين النماذج.
- **Agent:** نموذج مع تعليمات وأدوات وحالة مهمة محددة.
- **Orchestrator:** المنسق الذي يخطط ويوزع المهام ويتابع نتائجها.
- **Tool:** عملية يستطيع الوكيل طلب تنفيذها، مثل قراءة ملف أو تشغيل اختبار.
- **MCP:** بروتوكول لربط تطبيقات الذكاء الاصطناعي بخوادم الأدوات والسياق.
- **Skill:** حزمة تعليمات وموارد تساعد الوكيل على أداء نوع من المهام.
- **Context:** المعلومات التي ترسل إلى النموذج في الطلب الحالي.
- **Fallback:** الانتقال إلى بديل عند تعذر استخدام النموذج الأساسي.
- **Reasoning effort:** إعداد يحدد جهد الاستدلال الذي يدعمه نموذج/مزود معين، وليس مقياس ذكاء موحدًا.

أي تنفيذ يجب أن يطابق هذه الوثائق أو يوثق سبب تغييرها في سجل القرارات. لا تعتبر الأمثلة التزامًا نهائيًا قبل اختبار ملاءمتها.
