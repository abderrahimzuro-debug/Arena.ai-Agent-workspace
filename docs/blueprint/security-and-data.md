# الأمن والبيانات والصلاحيات

## 1. نموذج الصلاحيات

يوفر التطبيق وضعين:
- **Approval Mode:** يطلب موافقة المستخدم قبل العمليات التي تتجاوز القراءة أو قبل فئات محددة.
- **Autonomous Mode:** ينفذ تلقائيًا داخل حدود سياسة صريحة اختارها المستخدم.

لا يعني Autonomous Mode صلاحية مطلقة. تظل العمليات عالية الخطورة محمية، مثل الحذف الواسع، والكتابة خارج مساحة المشروع، وتشغيل أوامر غير معروفة، وتثبيت برامج، والوصول إلى أسرار، ورفع بيانات خارج الجهاز.

## 2. صلاحيات مستقلة

يحدد المستخدم السماح لكل فئة: قراءة الملفات، إنشاء/تعديل الملفات، الحذف، تشغيل أوامر محددة، الاختبارات والبناء، الإنترنت، خادم MCP، تثبيت Skills، عمليات Git المحلية، Push وإنشاء Pull Request.

## 3. مساحة العمل

يختار المستخدم مجلد مشروع واضحًا. يجب:
- منع اجتياز المسارات (path traversal).
- عدم اتباع symlinks إلى خارج الجذر دون موافقة.
- استثناء ملفات الأسرار افتراضيًا مثل .env وملفات المفاتيح.
- إنشاء checkpoint قبل التعديلات الواسعة.
- عرض diff قبل اعتماد التغييرات.
- توفير undo/restore.
- عدم تشغيل الكود تلقائيًا بعد كتابته.

## 4. تشغيل الأوامر

لا ترسل نصًا حرًا إلى shell من النموذج دون تحقق. استخدم أوامر مسموحة ومحددة المعاملات، وبيئة معزولة عند الإمكان، مع timeout وحدود موارد ومخرجات. اعرض الأمر وسبب تشغيله وفق مستوى الموافقة.

## 5. الأسرار

- خزّن API keys وGit credentials في Windows Credential Manager أو DPAPI.
- لا تحفظ الأسرار في README أو logs أو SQLite العادية أو Git.
- احجب الأسرار من رسائل الخطأ والسجلات.
- لا ترسل مفاتيح مزود إلى نموذج آخر.
- لا ترفع .env أو قواعد بيانات المستخدم إلى GitHub.
- وفر حذفًا وتدويرًا للمفاتيح.

## 6. التخزين

| البيانات | مكان التخزين |
|---|---|
| إعدادات التطبيق | SQLite أو ملفات إعدادات محلية |
| المحادثات | SQLite محليًا |
| Project/Task Memory | محليًا |
| فهرس الملفات | محلي وقابل لإعادة البناء |
| API keys / Git tokens | OS Credential Vault |
| سجلات الاستخدام | SQLite مع تنقية البيانات |
| ملفات المشروع | مجلد المشروع الذي اختاره المستخدم |
| النسخ الاحتياطي للمحادثات | اختياري، في مستودع خاص منفصل أو وجهة يختارها المستخدم |

لا تخلط مستودع كود التطبيق مع مستودع نسخ المحادثات. المزامنة اختيارية، وتحتاج تشفيرًا وموافقة واضحة.

## 7. خصوصية البيانات

قبل إرسال محتوى ملف إلى مزود خارجي، يجب أن يعرف المستخدم أن البيانات ستغادر جهازه. وفر استثناءات للمسارات والملفات، وعرضًا للمقتطفات المرسلة، وإخفاء الأسرار، وخيار تعطيل مزود، وسياسة حذف واضحة.

## 8. تهديدات الوكلاء

عامل محتوى الملفات وصفحات الويب والمستودعات والمهارات كمدخلات غير موثوقة. قد تحتوي على Prompt Injection. لا تسمح لمحتوى مسترجع بأن يغير سياسة النظام أو يمنح صلاحيات. الأداة هي التي تطبق السياسة، لا النموذج.
